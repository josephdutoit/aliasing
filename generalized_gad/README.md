# Generalized GAD experiment guide

This directory contains uploaded historical runs, their original scripts, and a
runner for making future outputs easier to reproduce and compare. Existing figures
and SLURM logs remain in place as historical evidence; they are not regenerated by
this guide. See [RESULTS_INDEX.md](RESULTS_INDEX.md) for a figure gallery.

## Experiment map

| Group | Scripts | Sweep and observable | Existing output |
| --- | --- | --- | --- |
| GLM GAD | `glm_gad_samplewise.py`, `glm_gad_featurewise.py` | Sample count or modeled feature count; dual-space error decomposition and information matrix norms | `{gaussian,logistic,poisson,exponential}_{samplewise,featurewise}.png` |
| Frozen sparse features | `frozen_superposition.py` | Bottleneck size; `||H⁺||₂` for linear and ReLU random features | `superposition_aliasing_mitigation.png` |
| Globally trained sparse features | `superposition.py`, `superposition_gaussian.py`, `superposition_no_bias.py` | Bottleneck size; compare trained and random features, with variants for noise and bias | `superposition_aliasing_bias_only.png`, `corrected_superposition_aliasing.png`, `clean_superposition_aliasing.png` (check the script for the exact filename of a run) |
| Embedded sparse features | `embedded_dd.py`, `embedded_superposition.py`, `superposition_full.py`, `aliasing_heatmap.py` | Latent dimension and/or hidden width; pseudoinverse norms, weight Gram, or regularization comparisons | `embedded_complexity_double_descent.png`, `superposition_mechanics.png`, `regularization_comparison_aliasing.png`, `aliasing_2d_phase_diagram.png` |
| Earlier GLM prototypes | `ggad_old/` | Historical alternative formulations | `ggad_old/*.png` |

Other historical figures in the directory may reflect intermediate script
revisions. The plots were uploaded without per-trial numerical data or a
machine-readable manifest, so do not assume every PNG corresponds exactly to the
current version of its similarly named script.

## Run and browse

From the repository root, install dependencies in your environment:

```bash
python -m pip install -e .
python -m pip install -r requirements-neural.txt scipy tqdm
python generalized_gad/experiment_cli.py list
python generalized_gad/experiment_cli.py run embedded-complexity --dry-run
python generalized_gad/experiment_cli.py run glm-samplewise -- --num-seeds 4 --num-workers 2
python generalized_gad/experiment_cli.py index
```

The runner invokes the original script with an absolute path and sets its working
directory to `generalized_gad/runs/<experiment>/<UTC timestamp>-<pid>/`. It saves
`manifest.json` (script hash, command, times, status, and generated PNG names)
and `stdout.log` alongside each figure. `runs/` is ignored by Git. To retain a
run, archive its directory externally or selectively commit validated outputs.
You can pass `--output-root /path/to/scratch` before `--` to use cluster scratch.
`index` writes an updated Markdown gallery that includes historical and new PNGs.

The two GLM scripts support the forwarded `--num-seeds` and `--num-workers`
arguments. The other scripts currently have expensive fixed sweeps, many of them
hardcode 28 processes, and `aliasing_heatmap.py` hardcodes **100 processes**.
Check the SLURM allocation before launching these scripts. The old `run.sh`
assumes a particular current directory and always launches the heatmap; the
CLI is the recommended entry point for new runs. The original scripts currently
save figures but not trial-level numerical results; their random-seed behavior
also varies by script. A run manifest records the code used, but cannot recover
the missing historical seeds or raw curves.

## What can be concluded from the current experiments?

1. The GLM sample and feature sweeps directly compute GAD-inspired error terms
   for the specified synthetic GLM models. They are a distinct experiment family
   from the neural representation experiments; consult the GLM code for its exact
   fitting and finite-value exclusions.
2. The neural sweeps establish **descriptive differences in the pseudoinverse
   norm** between random and learned feature matrices under the scripts' data
   distributions. Comparing linear and ReLU variants is a useful mechanistic
   probe. None of these plots alone measures held-out prediction error, actual
   decision-boundary aliasing, or the GAD aliasing term for a specified target.
3. The steep reduction just beyond `d=100` in
   `embedded_complexity_double_descent.png` could be caused by loss of rank:
   `||H⁺||₂` ignores directions whose singular values are zero or below SciPy's
   `pinv` tolerance. A smaller norm can therefore accompany **more lost
   information**. Record effective rank, full singular-value distribution,
   lost target energy, and held-out error before interpreting the reduction as
   successful mitigation.
4. In `embedded_dd.py`, `d` controls the number of possible generating features;
   each one is active with probability 0.05, so the mean active count rises from
   `0.05d` as `d` rises. The projection uses scale `1/sqrt(d)` as well. It does
   not isolate active-feature count at fixed latent dimension and fixed signal
   strength. Its fixed training sample count and hidden width are both 100.
   The vertical line `d=100` is a capacity reference, not an established
   interpolation threshold or evidence for generalization double descent.
5. `embedded_superposition.py` compares a latent **feature-by-feature** Gram
   matrix of shape `d × d` with an active **neuron-by-neuron** Gram matrix of
   shape `N × N`. Their off-diagonal Frobenius norms have different numbers of
   entries and different meanings, so their crossing is not a reduction in a
   common interference measure.

## Priority follow-up experiments

- Keep the number of possible features, embedding norm, sample count, and width
  fixed while varying the *exact number of active features per example*. Train
  a linear baseline and a ReLU model on identical data and measure held-out
  target error on new samples.
- Choose a label/readout with an explicit decision boundary; save both the
  decision margin and a GAD aliasing term for that target. Vary sparsity and
  capacity independently. Include trained linear, random ReLU, and learned
  ReLU controls, and ablate learned bias.
- Save individual seeds and per-trial CSV/NPZ measurements, including effective
  rank, singular values, activation rates, reconstruction error, test error,
  and an explicitly defined aliasing term. Report uncertainty across seeds.
- For a true double-descent claim, sweep model capacity through the *measured*
  interpolation threshold on a fixed train/test task; separately sweep data
  complexity to test how that curve shifts.

The existing results motivate these tests; they do not yet establish the
high-pass filtering, Marchenko–Pastur mechanism, or a double-descent theorem.
